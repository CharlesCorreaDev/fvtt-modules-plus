Como Publicar Módulos e Sistemas no Foundry VTT: Do Gratuito ao Pago no Marketplace Oficial

Por Mestre Charles Corrêa | Atualizado para Foundry VTT v14

Se você joga ou mestra no Foundry Virtual Tabletop (Foundry VTT), já deve ter se maravilhado com a infinidade de recursos disponíveis: iluminação dinâmica, animações de dados 3D, automações de combate e fichas interativas. Grande parte dessa magia vem da comunidade de criadores independentes.

No entanto, quando surge aquela centelha de criar a sua própria regra da casa, um tema de dados, um sistema completo ou uma aventura profissional, uma dúvida cruel paralisa quase todo mundo:

"Como eu coloco meu módulo no ar para as pessoas instalarem com um clique? E se eu quiser vender meu conteúdo, como funciona o Marketplace oficial do Foundry VTT?"

Neste artigo minucioso, vamos descomplicar todo o processo passo a passo, cobrindo desde a estruturação técnica básica até a homologação na vitrine oficial e os caminhos de monetização.

1. O Coração de Tudo: Entendendo o Manifesto (module.json / system.json)

Para o Foundry VTT reconhecer que uma pasta é um módulo ou sistema, ele exige um arquivo de manifesto em formato JSON na raiz do seu projeto:

  • Para módulos: module.json
  • Para sistemas de jogo: system.json

Esse arquivo contém o "DNA" do seu pacote. Veja os campos obrigatórios e mais importantes:

{
  "id": "meu-modulo-incrivel",
  "title": "Meu Módulo Incrível",
  "version": "1.0.0",
  "compatibility": {
    "minimum": "11",
    "verified": "14"
  },
  "authors": [
    {
      "name": "Mestre Charles Corrêa",
      "url": "https://rpg.charlescorrea.com.br",
      "discord": "charlescorrea"
    }
  ],
  "manifest": "https://raw.githubusercontent.com/usuario/repositorio/main/module.json",
  "download": "https://github.com/usuario/repositorio/releases/download/v1.0.0/meu-modulo-incrivel.zip",
  "readme": "https://github.com/usuario/repositorio/blob/main/README.md",
  "changelog": "https://github.com/usuario/repositorio/blob/main/CHANGELOG.md",
  "url": "https://github.com/usuario/repositorio"
}

Atenção aos Detalhes Críticos:

  • id: Deve ser único, em letras minúsculas e separado apenas por hífens. Não use espaços ou caracteres especiais.
  • manifest: URL direta (em texto puro) que sempre aponta para o module.json mais recente.
  • download: Link direto do arquivo .zip que o Foundry baixa ao clicar em Instalar.
  • Estrutura do .zip: Dentro do arquivo compactado, todos os arquivos devem estar dentro de uma pasta com o mesmo nome do ID (exemplo: meu-modulo-incrivel/module.json). Se descompactar os arquivos soltos na raiz do zip, o Foundry recusará a instalação!

2. Publicação de Pacotes Gratuitos no Diretório Oficial

O diretório oficial do Foundry VTT (foundryvtt.com/packages) é a vitrine que aparece diretamente no gerenciador de pacotes dentro do aplicativo de cada usuário no mundo inteiro.

Passo a Passo da Submissão Inicial:

  1. Crie e ative sua conta no site oficial: Acesse foundryvtt.com com uma licença vinculada.
  2. Acesse o Formulário de Submissão: Acesse diretamente foundryvtt.com/packages/submit.
  3. Preencha os dados do pacote:
    • Package Type: Módulo, Sistema ou Mundo.
    • Package ID: Exatamente o mesmo id do manifesto.
    • Package Title: O título público do pacote.
    • Package URL: Repositório Git (GitHub ou GitLab).
    • Discord Username: Insira seu usuário do Discord. Quando seu módulo for aprovado, você receberá automaticamente o cargo oficial de Developer no Discord do Foundry VTT!
    • Description: Texto formatado explicando o que o pacote faz, prints de tela e comandos.
    • Declaração de Inteligência Artificial: O Foundry possui uma política rígida (AI Content Policy). Conteúdos visuais e narrativos gerados por IA pública não são aceitos no diretório oficial sem permissão explícita. Deixe claro se o conteúdo foi criado humanamente.
  4. Aguarde a Moderação: A equipe do Foundry revisa manualmente o pacote (geralmente entre 24h e 48h úteis). Uma vez aprovado, seu módulo estará pesquisável por qualquer mestre!

3. Como Lançar Atualizações Automáticas: A Package Release API

Antigamente, cada atualização de versão exigia entrar no site do Foundry e editar o formulário na mão. Hoje, o Foundry oferece a Package Release API (documentação oficial).

Como Funciona:

  1. Na página do seu pacote aprovado no site do Foundry, você encontrará um campo chamado Package Release Token (começa com fvttp_...).
  2. Você guarda esse token em um local seguro (por exemplo, nos GitHub Secrets do seu repositório).
  3. Ao lançar uma nova tag no Git (ex: v1.0.1), uma esteira de automação (GitHub Actions) envia uma requisição POST direta para a API do Foundry:
curl -X POST "https://foundryvtt.com/_api/packages/release_version/" \
  -H "Content-Type: application/json" \
  -H "Authorization: fvttp_SEU_TOKEN_AQUI" \
  -d '{
    "id": "meu-modulo-incrivel",
    "dry-run": false,
    "release": {
      "version": "1.0.1",
      "manifest": "https://raw.githubusercontent.com/usuario/repositorio/main/module.json",
      "notes": "https://github.com/usuario/repositorio/releases/tag/v1.0.1",
      "compatibility": {
        "minimum": "11",
        "verified": "14"
      }
    }
  }'
Dica Técnica de Ouro: Nunca utilize comandos curl -s (silenciosos) nas suas Actions sem capturar o status HTTP! Se a API retornar erro (como 400 por manifesto indisponível ou 429 por limite de chamadas), o runner pode passar sem alertar ninguém. Sempre valide se o retorno foi HTTP 200.

4. Publicação de Módulos e Conteúdos Pagos: Os Modelos de Monetização

Muitos criadores de RPG produzem cenários autorais, compêndios gigantescos de monstros ou ferramentas complexas e desejam ser remunerados pelo seu trabalho. Existem dois caminhos consolidados no ecossistema:

Caminho A: O Marketplace Oficial do Foundry VTT (foundryvtt.store)

O Marketplace Oficial (foundryvtt.store) é a loja oficial gerida em parceria com a MetaMorphic Digital Studio.

Vantagens do Marketplace Oficial:

  • Proteção de Conteúdo e DRM Nativo: O cliente compra na loja logado com a conta do Foundry VTT. O pacote é liberado automaticamente na conta dele no aplicativo, sem necessidade de enviar chaves por e-mail ou lidar com pirataria manual.
  • Atualização Automática Transparente: O cliente atualiza o pacote diretamente pelo painel do Foundry, com toda a infraestrutura oficial da plataforma.

Regras e Exigências Importantes:

  • Contrato Comercial: É necessário formalizar uma parceria comercial de fornecedor (Content Provider) via e-mail formal com a MetaMorphic Digital Studio (foundry-marketplace@metamorphic-digital.com).
  • Piso de Preço: O valor mínimo absoluto aceito pela plataforma é de US$ 2,99 (com recomendação oficial a partir de US$ 4,99 devido a custos de processamento e retenções fiscais internacionais). Não é permitido cadastrar produtos gratuitos na vitrine de vendas da loja.
  • Proibição de PDFs Isolados: O Marketplace não é uma loja de livros digitais. É terminantemente proibido vender apenas PDFs avulsos. Todo produto deve ser um pacote Foundry completamente convertido (cenários prontos, atores com fichas configuradas, iluminação, paredes e tabelas).

Caminho B: Venda Independente (Patreon, Apoia.se, DriveThruRPG e Itch.io)

Se você prefere não assinar contratos corporativos ou deseja trabalhar no modelo de assinatura mensal com recompensas:

  • Patreon / Catarse / Apoia.se: Você pode disponibilizar o link de manifesto e o arquivo .zip em postagens exclusivas para apoiadores. Módulos populares como The Forge Bazaar ou integrações de terceiros permitem autenticar apoiadores.
  • DriveThruRPG: A maior loja de RPG do mundo possui convênio oficial com o Foundry VTT para venda de pacotes e geração de chaves autorizadas de ativação.
  • Itch.io ou Loja Própria: O comprador recebe o link do arquivo compactado ou acesso a um manifesto protegido e realiza a instalação manual colando a URL no Foundry VTT.

5. Checklist Final Antes de Publicar Qualquer Pacote

Antes de clicar em enviar no portal do Foundry ou disparar sua primeira tag, confira:

  • [ ] O arquivo module.json possui versão, título, ID e compatibilidade mínima/verificada válidas?
  • [ ] O arquivo .zip foi compactado contendo uma pasta com o ID do módulo na raiz interna?
  • [ ] Os links de manifest e download são públicos e estão respondendo com HTTP 200 (sem tela de login ou link quebrado)?
  • [ ] O código foi testado no console do Foundry (F12) sem erros de sintaxe ou avisos de métodos obsoletos?
  • [ ] Você incluiu um README.md atraente e um CHANGELOG.md documentando as novidades?
  • [ ] Se utilizou auxílio de ferramentas de IA para scripts, revisou e testou humanamente cada linha de código?
